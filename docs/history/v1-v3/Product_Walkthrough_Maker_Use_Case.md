"A Maker using MakerCAD User Case"
User launches program
start menu selects between new projects and continuing with existing ones
New project the user is prompted to first name then describe the project to the best of their ability
A linter looks for words phrases and other text based indicators that begin to pull potential tools for the user's Toolbox
example
User is prompted and Names the project "Custom desk Project" and describes the need to create a desk out of wood to use in a small and strangly shaped area of a room, where a previous bookshelf would of been. THe user has a 3d scan, a splat file, and the hard measurements. They have a list of materials available in their workshop, mostly plywood, some reclaimed boards, and drawer pulls and handles. The linter should pick up words like wood, plywood, measurments, file formats, and other clues built directly into the linter to find the right tools and make them readily available to the user. This is the method to hide all unnecessary tools that might be available and only present the ones the user needs. Expert users can toggle different tools to stay always available once the user understands their own workflow in the system. Tools that should be added to the toolbox sidebar in this case it would see the wood, the desk, the scans and understand the size it should be working at, user defines preferred system of measurement, so inches for most American users.
It would see the Reclaimed term, and the drawer pulls and handles and ask for photos of the boards that can be mapped to a 3d model so final design is viewable, or links to the drawer pull manufacturer, and existing stl or obj files, or more photos the user will be walked through creating the models. Once the pulls or handles are created, they live in a database locally and can be shared so that others might use the same created model freely. Tools it would need it would have to check if it can run Splats or 3d models, and then load the tools to allow the user to create a model based on the scan. Since splats do not have edges in the same way as photogrametry or other models, we will need to think through how the tool would work allowing the user to exist in the splat environment while still modeling a functional part using the information. We might need to see what others have done in this field currently to best take advantage of the best ideas available.
Once the user is satisfied with their toolbox, they can get started. there is a animated 3d character that exists in the MakerCAD workspace, that works as the assistant to the user. when something needs to be explained the character does this. The default character is about 5 foot 6 inches tall and should always be correct scale to the object we care creating. Our example uses a desk, so it would be in a generic room shape. The character would introduce itself, walk the user through the tools if needed, and generally works like a NPC in a roleplaying game. The Character asks if the user wants to use the model or splat as the environment, and loads the selection, staying in proper scale with the loaded environment. the likelihood that a model does not have the correct sizing is definitely possible, so we need to have tools to correct that from the beginning. Either by putting in measurements directly, or by drawing a box and adjusting the dimensions for the object to fit into.
Splats have the correct size info and the user uses the space to begin free model building the desk using primitive shapes to rough in the design. a materials estimator guesses out of the available inventory, how much material will be used. So the rough design is too thick and will use all of the wood and pywood beyond what is available. The user refines the design, using parametric controls to align the thickness of the boards in the design match what is listed in the inventory. The user can also design for things outside of their inventory, but this is to help make use of the the user has on hand first before exploring other options
The drawer pulls were vintage and do not have a model online. the user is prompted to take a photos from the top, sides, front, back, and bottom of the pull and walked through modelling it. It is then saved to be reused in any future project, or can be exported and imported by others. If existing models are available they can be loaded. This is one of the few places I this AI model generation might be most useful and appreciated, we can set that as experimental here.
Once the models exist, the user can right click and select use Part to use the pulls in the design.
once the desk is fully designed and material needs match the users budget and expectations, the user needs list what tools they have available to build, this actually should probably be much higher up in the process, perhaps when inventory is done of materials, the actual tools and workspace should be taken into account.
The tool should help you now break the design into actual steps to build the project, with a BOM, timelines, required order, and potential issues.
the final design should be printable as instructions to build the designed object.
Once the project has been completed the user is prompted to share images of the completed design. The completed plans, any corrections made can now be published or shared with others so that they can build from your design. Digital versions could exist as well where it would be loaded and take your personal inventory and tool list in account before telling you how to complete the build.
Others who might use MakerCad That are not Makers,
Video Effects and Animators
video game developers
They should both have their own workflow that is based on the above but wholely designed around those design needs and final output. We also want to plan ahead with flexability so that other potental users can find their own workflow for their niche needs.
